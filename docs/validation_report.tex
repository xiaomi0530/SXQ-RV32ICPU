\section{Benchmark 性能验证}

\subsection{总体结果}

Benchmark 汇总结果如表~\ref{tab:benchmark_summary} 所示。需要特别说明的是，CoreMark 的 Score 与微架构统计指标采用不同采集口径：\texttt{275.921925 Iter/s} 来自 \texttt{ITERATIONS=5000} 的实际上板运行 UART 输出；CoreMark 的周期数 \texttt{C}、退役指令数 \texttt{I}、IPC 以及后文跳转分支预测准确率，则来自 \texttt{ITERATIONS=1} 的 Vivado 仿真统计。这样处理的原因是，CoreMark 官方性能成绩需要足够长的上板运行时间保证有效性，而周期级退役统计和预测器事件统计在仿真中运行 \texttt{5000} 次迭代会显著增加验证时间；单次迭代仿真仍覆盖 CoreMark 的主要程序路径，可用于表征当前微架构的周期、退役与控制流行为。IPC 统计采用 testbench 中有效运行窗口内的后端退役口径，即统计周期数 \texttt{C} 与退役指令数 \texttt{I}，并计算
\[
    \mathrm{IPC}=\frac{I}{C}.
\]

\section{分支与跳转预测准确率}

分支/跳转预测统计采用 CoreMark 单次迭代 Vivado 仿真数据，区别于上板 5000 次迭代的 UART 性能输出。采用该口径是为了在合理仿真时间内获得周期级控制流事件统计。方向准确率表示控制流方向预测正确比例；目标准确率表示预测 taken 或跳转目标时目标地址正确比例；总体准确率为综合方向与目标后的控制流预测正确比例。

该结果说明当前版本以一定 LUT 增量换取了明显的 CoreMark 性能提升，并在 \texttt{100 MHz} 下保持 post-route 时序收敛。

\section{结论}

当前版本 \texttt{SXQ-RV32IM CPU} 已在 \texttt{xc7a100tcsg324-1} FPGA 上完成实现，post-route 时序满足 \texttt{100 MHz} 约束。Benchmark 方面，CoreMark 上板 \texttt{5000} 次迭代运行达到 \texttt{275.921925 Iter/s}，Dhrystone 达到 \texttt{166000 Dhrystones/s}、即 \texttt{0.945 DMIPS/MHz}，Embench-WikiSort 得分为 \texttt{122.58}。CoreMark 单次迭代仿真窗口内 IPC 为 \texttt{0.851}，总体控制流预测准确率为 \texttt{88.43\%}；JAL/JALR 预测准确率接近完全正确，主要预测损失来自 B 型条件分支方向预测。

FPGA 资源方面，当前设计占用 \texttt{3581} 个 LUT、\texttt{2741} 个 FF、\texttt{16} 个 BRAM Tile 和 \texttt{4} 个 DSP，LUT 占用率仅 \texttt{5.65\%}。功耗方面，总片上功耗为 \texttt{0.329 W}，动态功耗为 \texttt{0.231 W}，结温为 \texttt{26.5}$\,^{\circ}\mathrm{C}$。综合来看，当前版本在较低资源与功耗开销下实现了较高的单发射流水线性能，并通过 benchmark 与 FPGA 实现报告形成了较完整的验证闭环。
